# Trialvault 试验数据版本库

使用内容寻址文件和本地目录库保存试验数据。支持结构契约、导入、投影连接、汇总、质量检查和经过批准的版本导出；撤回状态会影响发布资格。

## 分类实验

试验数据可以绑定为受控的分类实验。实验定义固定数据版本、特征列、标签列和批次身份，并记录调用者给出的误判成本。划分按批次整体进行：同一批次的试片不会拆到训练与验证两侧，最终留出集由时间最晚的批次组成，且必须严格晚于全部训练批次，否则定义被拒绝。

缺失填充、类别编码、特征筛选和调参都只在每个训练折内拟合；全空列和常量列被丢弃并记录原因，未知类别在转换时编码为零块并逐行注明。首版比较正则化逻辑回归、一个决策树和多数类基线，按交叉验证的期望误判成本选型并确定阈值。留出集只评估一次：同一留出批次被任何实验消费后，其他实验不能再用它做留出评估。运行结果包含混淆矩阵、PR 数据、阈值和分批表现；某折没有正例或数据只有一个类别时，结果会明确说明能得出什么结论，不会静默跳过。

训练好的模型可以对新数据评分：输入先校验 schema，解释（线性贡献或决策路径）只由特征和存储参数推出，不读取目标标签。输入版本被撤回或制品损坏时，实验成品变为无效并拒绝评分；出现更新的数据版本时，成品标记为已过时。

## 运行环境

使用 Python 3.11，核心功能依赖标准库和 SQLite。演示和测试只使用本地合成数据，不需要账户、设备或外部运行服务。请从项目根目录执行命令。

数值分析依赖固定在 requirements.txt。安装在独立环境中，准备完成后可离线使用；已有版本库功能不依赖这些分析包。

```sh
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements.txt
```

## 检查与运行

构建检查验证语法，测试使用临时数据目录，不会连接远端服务。

```sh
python3 -m compileall -q trialvault
python3 -m unittest discover -s tests -v
python3 -m trialvault demo
```

演示会展示产品的实际数据处理和输出，运行结束自行退出。查看现有接口：

```sh
python3 -m trialvault --help
```

## 目录与数据

trialvault/ 保存领域逻辑和请求入口，tests/ 包含正常行为、边界与恢复测试。例子中的标识和记录为合成资料，不包含真实人员或生产测量。业务目录和本地数据库由调用者指定，应与源码分开保存。

## 干净环境复现

容器定义固定运行时版本。构建时准备环境，运行时无需网络；每次启动会复制只读源码到临时工作目录，测试产生的文件不会写回仓库。

```sh
docker build -t local-product-check .
docker run --rm --network none local-product-check
```
